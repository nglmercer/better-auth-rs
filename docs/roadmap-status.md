# Roadmap status

This file tracks [better-auth-rs-implementation-roadmap.md] item by item. Each
line says what the code does today and what is missing. Statuses:

- **Done**: implemented and covered by a test in this repository.
- **Partial**: some of the item works, and the rest is listed.
- **Not started**: no implementation.

"Done" does not mean production-ready. The parity claims per feature are in
[parity/MATRIX.md](parity/MATRIX.md). Tests named below are in
`crates/better-auth/src/` unless a path is given.

Live-database tests need the environment variables in
[live-tests.md](live-tests.md). Without them they skip.

## Current goal

Narrowed on 2026-10-31 from "implement the whole roadmap", which cannot be met in this repository.
The goal is that every upstream core endpoint is either mounted, or listed in
[parity/DEFERRED.md](parity/DEFERRED.md) with the reason it is not built. CI runs
`tools/parity/check_deferred.py`, which fails when a missing endpoint has no reason or a deferred
endpoint has since been mounted. Status at this point: 96 of 128 mounted, 32 deferred with reasons.
The roadmap's items stay open where they are listed as Partial or Not started below.

## Phase 1: security blockers

| Item | Status | Evidence and gaps |
|---|---|---|
| P1-01 Privileged route authorization | Partial | A central access table, `route_access` in `router.rs`, states what each built-in route requires: public, a session, an administrator, or a SCIM bearer token. Unlisted routes require a session. The gate runs before routing (`tests/route_policy.rs`): the table matches the OpenAPI route list, anonymous callers are refused on every session route, and non-administrators on every admin route except the permission check. Plugin endpoints keep their own access levels. Missing: rate-limit policy per route, and direct service-call tests for each entry point. |
| P1-02 CSRF, origin, Fetch Metadata | Partial | State-changing requests follow an explicit policy (`check_csrf` in `security.rs`, `tests/csrf_policy.rs`). A present `Origin` must be a trusted origin, and `null` is never trusted. A present `Sec-Fetch-Site` must be `same-origin`, `same-site` or `none`. When the two disagree, the request is refused. Absent headers are accepted, for non-browser clients only. Safe methods are not checked. The OAuth begin and callback routes use GET for the provider redirect, and they carry their own state checks. Missing: proxy-boundary tests. |
| P1-03 OAuth state | Done | Single use in every mode; signed-cookie mode requires storage (`oauth.rs`: `signed_cookie_state_is_single_use_with_storage`); redirect URIs must be trusted HTTPS (`redirect_uri_must_be_https_and_trusted`). |
| P1-04 Provider email trust | Partial | Missing email is `false`. GitHub uses verified `/user/emails`. Facebook never reports a verified email. Google ID tokens are validated, including `sub` against userinfo (`http_oauth.rs`), but signing keys must be loaded with `google_with_jwks`, and there is no scheduled refresh. Duplicate-identity rejection exists. |
| P1-05 Draft PR #2 | Partial | PR #2 (`fix/1-legacy-oauth-ids`) was merged into the working tree with my changes, and its tests pass together. Not pushed or merged on GitHub. Issue #1 needs host-application E2E, which this repository cannot provide. |
| P1-06 2FA before session | Done | Enabled 2FA gives a challenge, not a session, on password and OAuth sign-in (`router.rs`: `two_factor_challenge_gates_sessions_and_codes_are_single_use`). |
| P1-07 Rate limits | Done | Per-IP (when a trusted proxy supplies it) and per-account buckets for sign-up, sign-in, username sign-in, reset request, verify, reset, magic link, email code, two-factor and account changes. Shared atomic store (`rate_limit.rs`). Responses do not reveal account existence. |
| P1-08 Errors and body limits | Partial | Internal errors return `500 internal server error` with an `x-request-id`, and the detail is logged under that ID. Bodies are capped at 2 MiB and oversize returns 413. Missing: metrics. |
| P1-09 Side effects on error | Partial | Sign-up, OAuth and session creation compensate on hook failure (`failed_session_hook_leaves_no_orphan_session`). Password policy and OTP attempt limits exist. Input parsers are checked with deterministic property tests over every public route and the SCIM filter (`tests/input_properties.rs`). Missing: a fuzzer that runs without a bound. |

| P4-06 SSO and OIDC | Partial | Service: OIDC ID-token validation and provisioning (`oidc.rs`, `plugins/sso.rs`). Missing: discovery and routes. |

The current key cannot be retired. `GET /jwks` and `GET /.well-known/jwks.json` publish every key in the overlap. Missing: client-credentials tokens and an automatic rotation schedule. |

## Round notes

Items updated in the latest round (see the tables above for the current status):

- P5-03 (load): in-process measurements recorded in `docs/operations/LOAD_TEST.md`.
  Multi-node, networked, and chaos tests are still open.
- Account enumeration timing: unknown addresses now pay the same hashing time
  as real accounts (`unknown_address_pays_the_same_hashing_cost_as_a_known_one`).
- Phase 8: TypeScript, Rust and Kotlin clients now cover the account, two-factor,
  passwordless, API key, device and anonymous routes. Kotlin tests run with
  `JAVA_HOME=/usr/lib/jvm/java-21-openjdk ./gradlew jvmTest` (JDK 27 is too new
  for the pinned Gradle).
- Phase 7: device authorization (RFC 8628), HIBP range screening
  (`security_checks.rs`) and CAPTCHA verification (Turnstile) are implemented
  behind traits, with fail-open or fail-closed policy chosen explicitly.
- Phase 6: anonymous guests (upgrade keeps the user id), last-login method.
- Phase 9: compatibility fixtures (`crates/better-auth/tests/compat/`), CHANGELOG,
  SECURITY.md, and the release policy in `docs/governance/RELEASE.md`.
